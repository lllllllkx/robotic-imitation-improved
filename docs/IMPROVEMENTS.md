# 在论文基础上做的三处改进

**定位**：这是 RSS 2020 动物运动模仿方法（Peng et al.）的**仿真复现 + 改进研究**，
不是论文全部实验的复现——潜在空间自适应 / AWR、真机实验、全量 PPO 训练都没有做（见文末）。

论文与官方实现给出的基线本身是可靠的：我们按 `docs/REPRODUCTION.md` 跑官方预训练策略，
`dog_pace` 单回合每步奖励 0.7496、`dog_spin` 0.6378。注意这两个数与论文 Table V
（Robust：`dog_pace 0.820`、`dog_spin 0.839`）**不是同一种口径**，不能直接比：
论文那条是"仿真、canonical 动力学、3 个独立训练策略平均"，我们这里是"单份发布策略、
确定性 t=0 起点、单回合"。仓库里没有记录这两份预训练策略的训练配置，而上游 `run.py`
用的又是 `4096 / 1 epoch / 1e-5`（论文 Table II 是 `10000 / 10 epochs / 2e-5`），
因此这个差距究竟来自评估口径还是训练预算，**在没有重训的条件下无法判定**。

下面三处改进都来自复现过程中**实测到的**问题，不是纸面设想；每一处都给出改前/改后的数字。

所有改动都在 `src/env_patch.py` 里以运行期 monkey-patch 实现，`third_party/motion_imitation/`
一个字节都没有改；三个开关默认关闭，关闭时走"上游兼容基线路径"（口径说明见文末）。

---

## 改进 1：每个步态周期重锚定参考朝向（无界偏航漂移 → 有界周期误差）

**问题（来自代码 + 实测）**
上游 `ImitationTask._update_ref_motion()` 在每个步态周期做一次参考原点同步：

```python
self._sync_ref_origin(sync_root_position=True,
                      sync_root_rotation=change_clip)   # 只有换 clip 时才同步朝向
```

也就是说，位置每周期被重锚定，**朝向只在切换动作片段时同步**。对于 `dog_spin` 这类
原地循环转向的技能，机器人实际转速与参考片段的名义转速对不上，误差在起步后约 1 个步态周期
内就跳到 −0.65 rad，随后继续以约 −0.023 rad/s 缓慢累积，20 s（600 步）时到 **−1.08 rad**，
整回合平均绝对偏航误差 0.8157 rad；同时 `root_pose` 分项从 0.907 掉到 **0.000**
（整回合均值 0.038）。

这里要说准确：奖励**看得到**这个误差（`root_pose` 项直接把它压到底），但策略在当前的
参考系里学不到怎么消除它——参考朝向本身在滑，机器人怎么走都补不回来。于是 15% 的权重被
一个**消除不掉的朝向误差**锁死：每步都稳定地扣分，却不再随策略改善而变化，只有扣分没有指向。

**改动**
`enable_cycle_heading_anchor(env)` 把同一个函数重写成
`sync_root_rotation=True`（每个周期位置与朝向一起重锚定）。上游内部就是用 `_calc_heading()`
算两个朝向的差值，再构造绕 Z 轴的四元数，所以同步的确实是 **heading**，不是完整三维姿态。
物理上等价于"每个周期把参考朝向对齐到机器人当前朝向再算误差"，把无界累积变成有界周期误差。

**结果（官方预训练策略，无需任何重新训练）**

3 seeds × 3 回合、随机参考相位、每回合 600 步（run `r20261114`）：

| 技能 | 指标 | 上游基线 | + 朝向重锚定 | 变化 |
| --- | --- | --- | --- | --- |
| dog_spin | 平均奖励 | 0.6980 ± 0.0074 | **0.7602 ± 0.0014** | **+8.9%** |
| dog_spin | 偏航误差 (rad) | 0.2804 | **0.0537** | **−80.9%** |
| dog_spin | 关节误差 (rad) | 0.0502 | 0.0475 | −5.4% |
| dog_spin | 根误差 (m) | 0.0679 | 0.0660 | −2.8% |
| dog_spin | 水平速度 (m/s) | 0.1128 | 0.1069 | −5.2% |
| dog_spin | `root_pose` 分项 | 0.5513 | **0.8298** | +50.6% |
| dog_pace | 平均奖励 | 0.7481 ± 0.0026 | 0.7521 ± 0.0014 | +0.5% |
| dog_pace | 偏航误差 (rad) | 0.0631 | **0.0335** | **−46.9%** |
| dog_pace | 根误差 (m) | 0.0261 | **0.0239** | −8.4% |

确定性单回合（受控 t=0 起点）对比更极端：`dog_spin` 奖励 0.6378 → **0.7609（+19.3%）**，
平均偏航误差 0.8157 → **0.0565**（14.4 倍），带符号漂移斜率 −0.0232 → **+0.0029 rad/s**，
`root_pose` 分项 0.038 → **0.834**。

`dog_pace` 的收益小是合理的：直线步态本身不累积朝向误差，重锚定只是把每周期的一点点
相位偏差清掉，因此奖励几乎不动（+0.5%），但偏航误差降了 47%、根误差降了 8%。

**一个必须说明的偏差**：重锚定改变的是**参考坐标系**，所以上面这些误差是在"每周期重新对齐
过的参考系"里算的。要区分"真实跟踪改善"与"目标被对齐后误差自然变小"，还需要在同一条轨迹
上按**固定参考系**再算一遍——本仓库尚未提供这个口径，因此结论应读作"在周期对齐的参考系下，
朝向跟踪误差与奖励都改善了"，而不是"机器人本身变得更会原地转向"。

## 改进 2：速度奖励项去饱和 + 权重重配平（训练侧改动）

**问题**
上游速度项是

```python
exp(-0.1 * sum_j (dq_ref - dq_sim)^2)     # 12 个关节求和
```

在 `dog_pace` 上用官方策略实测：9 回合 × 600 步 = 5400 步，`term_velocity` 直接取自
`task.reward()` 内部（每一步的 5 项加权和与该步 `reward` 逐位对齐，误差 0.000000）。
反解出的 `sum_j Δdq²` 中位数 87.3（p10 48.9、p90 146.0、均值 92.1），即单关节
RMS 约 **2.7 rad/s**。**这一项自己的取值分布**是

| 统计量 | p10 | p50 | 均值 | p90 | 最大值 |
| --- | --- | --- | --- | --- | --- |
| 速度项实测值 | 4.6e-7 | 1.6e-4 | **2.6e-3** | 7.5e-3 | 0.041 |

也就是 92.8% 的步里这一项低于 0.01、100% 低于 0.05，却带着 0.05 的权重——
**奖励信号严重饱和**，加权后对优势函数的贡献只有 `0.05 × 2.6e-3 ≈ 1.3e-4`（总奖励的 0.02%）。

这里有三处必须分开的说法（早期版本把它们混在一起，是错的）：

- `exp(-0.1 × 92.1) = 1.0e-4` 是**把平均误差代入奖励函数**得到的估计值，不是实测平均奖励；
- 实测平均是 2.6e-3，比它高 **26 倍**，因为 `E[exp(-0.1·E)] ≠ exp(-0.1·E[E])`（Jensen
  不等式，exp 是凸函数，均值必然不小于 1.0e-4）；
- exp 随误差单调递减，**误差的 p90 对应奖励的下尾**：`exp(-14.6) ≈ 4.5e-7` 正好落在奖励
  p10（4.6e-7）上，不能读成"奖励 p90"。
- 旧文档里的 p10 0.0002 / p50 0.0043 / 均值 0.0157 / p90 0.0476 是**旧文档误算值**：
  那批数取自 `reproduction/outputs/eval/*/steps.csv`，而该 CSV 的奖励分项是在 `env.step()`
  之后重算的（参考状态已经推进），加权和与实际 `reward` 平均差 0.107，整条分布不可用。
  上面这张表是本次用 `task.reward()` 内部 tee 出来的值重算的。

**注意一个容易踩的坑**：仅仅"改成按关节取平均"是恒等变换，因为
`12 × 0.1 = 1.2`，`exp(-1.2 · mean)` ≡ `exp(-0.1 · sum)`。真正的改动必须同时改尺度。

**改动**
`apply_velocity_reward_v2(env)`：

1. 速度项按关节数取均值，尺度从 0.1 改为 0.25，同一个工作区间被映射到
   `[0.53, 0.16]`（均值 0.34），信号重新变得有梯度（**注意**：这里说的是奖励函数的形状，
   不等于说重训后策略一定更好，PPO 优化的是优势，不是直接对奖励求梯度）；
2. 五项的权重从 `pose 0.50 / vel 0.05 / ee 0.20 / root_pose 0.15 / root_vel 0.10`
   改为 `0.45 / 0.10 / 0.20 / 0.15 / 0.10`——从唯一有余量的姿态项让出 0.05，
   **五项权重和恒为 1.0**（代码里有断言）。这一点是关键：权重和为 1 意味着
   "每步奖励 ∈ [0,1] 且 1.0 = 完美跟踪"，`mean(reward)` 仍然是 [0,1] 区间里的归一化回报
   （但见下方边界：v2 的数值与 v1 不同口径，不能直接比大小）。

**结果（同一段轨迹、只改奖励读数，策略行为不变）**

| 项 | 上游 v1 | v2 |
| --- | --- | --- |
| 速度项 p10 / p50 / p90（5400 步） | 4.6e-7 / 1.6e-4 / 7.5e-3 | **0.048 / 0.162 / 0.361** |
| 速度项均值 | 2.6e-3 | **0.191**（73×） |
| 速度项最大值 | 0.041 | 0.515 |
| 加权贡献（权重 × 均值） | 1.3e-4（占 0.02%） | **1.9e-2（占 2.6%）** |
| `pose` 加权贡献 | 0.4488 | 0.4031（权重 0.50 → 0.45） |
| 同回合关节/根/偏航误差 | 0.0651 / 0.0261 / 0.0631 | 完全相同（策略未被改变） |
| 每步奖励（9 回合随机相位） | 0.7481 | 0.7222 |

**边界（必须说清楚）**：这是纯训练侧改动，它的价值只有在重新训练后才能兑现。本机无 GPU，
论文每技能约 2e8 采样按实测 70 步/秒需要约 33 天/技能/种子，因此**没有**做端到端训练验证；
仓库只给出"奖励项已不再饱和"的直接证据和可直接复用的开关。也正因为改了尺度，
`--reward-v2` 下的奖励数值**不能**与论文/基线的奖励直接比大小，跨配置比较要看
关节误差、偏航误差、速度这些与奖励定义无关的量。

## 改进 3：扩展评估协议（多初始条件 + 分层统计）

**问题**
上游 `eval_pretrained.py` 的评估是"5 个回合、每回合都从参考片段 t=0 开始"，
由于环境无随机化，5 个回合的逐帧数据完全一致——本质上是**一次确定性回放**，
既没有误差棒，也系统性高估/低估策略在真实起点分布下的表现。

**改动**
`src/evaluate.py` 提供的是一套**扩展**协议，不是论文原协议（区别见下）：

- `--seeds N`：多个评估种子，逐 `(seed, episode)` 从 `RandomState(1000·seed + ep)` 抽取起始相位；
- `--random-phase`：每回合在参考片段上随机取相位（与上游 `_enable_rand_init_time` 同分布，
  但**由本仓库显式生成**，因此跨进程可复现——上游采样器所依赖的 RNG 从外部无法固定）；
  参考 clip 是 `LoopMode.Wrap`、`is_over` 恒 False，所以随机起点不会导致提前终止；
- `--start-phases "0,0.25,0.5,0.75"`：确定性相位栅格，用于配对消融；
- `--upstream-init`：保留上游初始状态分布（`ref_state_init_prob=0.9`、随机起始时间），
  不加这个开关时是**受控模式**（永远从参考状态起步、相位由我们指定），用于配对比较；
- 输出 `mean ± std`（按回合池化）、`by_seed` 两层级统计（先算每个种子的回合均值，再
  对种子求 mean/std）、末 5 s 窗口均值、展开后的带符号偏航误差斜率 `yaw_drift_rad_per_s`、
  水平速度与三维速度、以及终止原因 `termination`（`time_limit` / `early_termination`）；
- 每回合把 5 个奖励分项单独落盘，并在 `task.reward()` 内部 tee 出**该步实际使用的**分项值，
  用它们反算加权和与 `mean(reward)` 逐回合核对（`reward_from_terms` 与 `mean_reward` 相等）。

**和论文的差别（必须写清楚）**
论文 Table V 是**仿真、canonical 动力学、3 个独立训练策略求平均**；
这里的 `--seeds` 只改变**评估初始条件**，策略是同一份。所以本协议回答的是
"单个策略对起始条件的敏感性"，不是"训练结果的稳定性"。若要看后者，必须训练 3 个不同
初始化的策略，这部分本仓库没有做。

**结果：协议本身揭示了基线评估的偏差**

| 技能 | 单回合确定性（上游口径） | 3 seeds × 3 回合随机相位 | 差异 |
| --- | --- | --- | --- |
| dog_spin | 0.6378 | 0.6980 ± 0.0074 | +9.5% |
| dog_pace | 0.7496 | 0.7481 ± 0.0026 | −0.2% |

`dog_spin` 的确定性口径把成绩低估了近 10%（t=0 起步包含一段朝向误差累积的暂态，
而且只有一条轨迹、没有误差棒），这正是单回合评估最容易掩盖的问题。随机相位协议下
9 个回合的标准差 0.0074 也说明这个技能本身对起点并不敏感——低估值来自固定起点，而不是随机性。

**再钉一颗钉子：受控起点 vs 上游初始分布。**`--upstream-init` 保留上游的
`ref_state_init_prob=0.9` 与随机起始时间，其余条件不变（同样 3 seeds × 3 回合、随机相位）：

| 技能 | 受控模式（本文主表） | 上游初始分布 | 差 |
| --- | --- | --- | --- |
| dog_pace | 0.7481 ± 0.0026 | 0.7488 ± 0.0019 | +0.1% |
| dog_spin | 0.6980 ± 0.0074 | 0.7013 ± 0.0068 | +0.5% |
| dog_pace 偏航误差 | 0.0631 | 0.0597 | −5.4% |
| dog_spin 偏航误差 | 0.2804 | 0.2701 | −3.7% |

差别在 1% 量级，说明"永远从参考状态起步"这个受控假设**没有**系统性抬高成绩——
它是为了配对比较（不同变体必须同起点），而不是为了把数字做好看。同时这也说明，
和论文 Table V 的差距不能归因于起点选择：真正的差别在单策略 vs 3 个训练策略、
以及有没有域随机化。

## 可复现性：上游兼容基线路径

`src/env_patch.py` 的三处 patch 都只在显式开关下生效（`--yaw-anchor` / `--reward-v2` /
`--random-phase` / `--upstream-init`）。不带任何开关时，`src/evaluate.py` 在同一套依赖、
同一起点、同一策略下得到的平均奖励与官方 `eval_pretrained.py` 一致（`dog_pace` 0.7496、
`dog_spin` 0.6378），因此可以当作上游评估的替代品使用。

**这句话的边界要说清**：这是"summary 级一致"，不是"逐位一致"。仓库里**没有**做逐步的
`(状态, 观测, 动作, 奖励)` 回归测试；而且本次运行的 pybullet 是 3.2.0、upstream 依赖是
2.7.3（物理引擎版本不同，轨迹本来就不可能逐位相同）。所以在文档里统一改成
"上游兼容基线路径"，只有在补齐逐步回归并锁定依赖版本之后才适合说"逐位一致"。

### 为了让"同一命令两次跑出同一数字"成立，踩过的三个坑

1. **TF/BLAS 线程数**：默认线程池下同一策略、同一种子在两次进程里会出现 1e-7 量级差异，
   对 `dog_spin` 这种接近稳定边界的步态足以让 600 步后轨迹分叉（实测同一配置两次跑出
   0.63 与 0.70）。线程变量现在在**导入 numpy 之前**就置 1（早期版本写在 `build_env()` 里，
   那时 numpy 已经导入，是否生效没有保证）。
2. **随机相位采样**：`ImitationTask._rand_uniform()` 在 env 没有 `np_random` 时回落到全局
   `np.random`，而该状态无法从外部固定，导致"随机相位"运行不可复现。受控模式下不再调用
   上游采样器，改为按 `(seed, episode)` 显式生成相位并写入 summary。
3. **初始状态分布**：上游 `ref_state_init_prob=0.9`（90% 从参考状态起步，其余随机），
   且默认开启随机起始时间。受控模式把它固定为 1.0 并关闭随机时间采样，保证不同变体
   从同一状态出发；`--upstream-init` 则恢复上游分布，用于单独检查"与官方环境的对齐程度"。

固定之后，同一条命令在两个独立进程里逐回合数值完全相同（已用 2 进程 × 2 回合 × 300 步
核对：`reward` 与 `start_phase` 完全一致）。

### 评估器本身的几处修正（相对早期版本）

- **yaw 提取**：早期用 `2·atan2(qz, qw)`，只在 roll=pitch=0 时成立；现在用完整公式
  `atan2(2(wz+xy), 1-2(y²+z²))`。由于本机四足姿态的 roll/pitch 很小，数值变化在第 3 位小数，
  但公式不再依赖"机身水平"这个假设。
- **漂移指标**：早期把**包裹后的绝对值**误差拿去拟合斜率，误差越过 ±π 会折返，斜率会失真。
  现在两条曲线分开：`mean_yaw_err_rad` = 包裹绝对误差（跟踪精度），
  `yaw_drift_rad_per_s` = 展开后的**带符号**误差做最小二乘斜率（累积趋势）。
- **速度**：`mean_speed_mps` 改为水平速度（步态速度），另存 `mean_speed_3d_mps`
  （含机身上下起伏），避免把颠簸算成前进速度。
- **终止原因**：`survived` 之外新增 `termination`，区分 `time_limit` 与 `early_termination`。

### `reproduction/` 目录里的旧产物（legacy，勿引用其统计）

`reproduction/` 是第二阶段在隔离工作区产出的交付物。其中的 `outputs/eval/*/steps.csv`、
HTML 报告与 `复现说明` 用的是**旧口径**：yaw 取 `2·atan2(qz, qw)`，奖励分项在 `env.step()`
之后重算（加权和与实际 `reward` 平均差 0.107），速度项分布也由这批错位数据推出。
这些文件保留作为历史记录，**不要**引用其中的偏航数字与奖励分布；新结论一律来自
`results/eval/*/summary.json` 与 `results/summary_table.md`。

## 没有做、也建议不要当作已完成的事
