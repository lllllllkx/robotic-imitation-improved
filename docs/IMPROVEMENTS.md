# 在论文基础上做的三处改进

论文与官方实现给出的基线本身是可靠的：我们按 `docs/REPRODUCTION.md` 跑官方预训练策略，
`dog_pace` 单回合每步奖励 0.7496、`dog_spin` 0.6378，和论文 Table V 的量级一致。
下面三处改进都来自复现过程中**实测到的**问题，不是纸面设想；每一处都给出改前/改后的数字。

所有改动都在 `src/env_patch.py` 里以运行期 monkey-patch 实现，`third_party/motion_imitation/`
一个字节都没有改；三个开关默认关闭，关闭时与上游逐位一致（可复现性见文末）。

---

## 改进 1：每个步态周期重锚定参考朝向（无界偏航漂移 → 有界周期误差）

**问题（来自代码 + 实测）**
上游 `ImitationTask._update_ref_motion()` 在每个步态周期做一次参考原点同步：

```python
self._sync_ref_origin(sync_root_position=True,
                      sync_root_rotation=change_clip)   # 只有换 clip 时才同步朝向
```

也就是说，位置每周期被重锚定，**朝向只在切换动作片段时同步**。对于 `dog_spin` 这类
原地循环转向的技能，策略实际转速与参考片段的名义转速之间存在每周期约 0.05 rad 的偏差，
这个偏差不会被清除，而是随周期数线性累积。实测确定性回合（t=0 起步、600 步 = 20 s）：
偏航误差从 0.06 rad 单调涨到约 1.0 rad，平均 0.80 rad，而 `root_pose` 分项仍高达 0.93——
奖励函数几乎"看不见"这个漂移。

**改动**
`enable_cycle_heading_anchor(env)` 把同一个函数重写成
`sync_root_rotation=True`（每个周期位置与朝向一起重锚定）。物理上等价于"每一步都把参考
朝向对齐到机器人当前朝向再计算误差"，把无界累积变成有界周期误差。

**结果（官方预训练策略，无需任何重新训练）**

3 seeds × 3 回合、随机参考相位、每回合 600 步：

| 技能 | 指标 | 上游基线 | + 朝向重锚定 | 变化 |
| --- | --- | --- | --- | --- |
| dog_spin | 平均奖励 | 0.6980 ± 0.0074 | **0.7602 ± 0.0014** | **+8.9%** |
| dog_spin | 偏航误差 (rad) | 0.2510 | **0.0473** | **−81%** |
| dog_spin | 关节误差 (rad) | 0.0502 | 0.0475 | −5.4% |
| dog_spin | 根误差 (m) | 0.0679 | 0.0660 | −2.8% |
| dog_pace | 平均奖励 | 0.7481 ± 0.0026 | 0.7521 ± 0.0008 | +0.5% |
| dog_pace | 偏航误差 (rad) | 0.0751 | **0.0286** | **−62%** |
| dog_pace | 根误差 (m) | 0.0261 | **0.0239** | −8.4% |

确定性单回合（论文式 t=0 起点）对比更极端：`dog_spin` 奖励 0.6378 → **0.7609（+19.3%）**，
偏航误差 0.8017 → **0.0460**（17 倍），漂移斜率 +0.0233 → **−0.0026 rad/s**。

`dog_pace` 的收益小是合理的：直线步态本身不累积朝向误差，重锚定只是把每周期的一点点
相位偏差清掉，因此奖励几乎不动（+0.5%），但偏航误差降了 62%、根误差降了 8%。

## 改进 2：速度奖励项去饱和 + 权重重配平（训练侧改动）

**问题**
上游速度项是

```python
exp(-0.1 * sum_j (dq_ref - dq_sim)^2)     # 12 个关节求和
```

在 `dog_pace` 上用官方策略实测：`sum_j Δdq²` 的均值 57.5（p10 30.4、p90 87.7），即单关节
均方误差 4.8 rad²/s²（RMS 2.19 rad/s）。于是这一项的取值是

- 均值 `exp(-5.75) = 0.0157`
- p90 `exp(-8.77) = 1.5e-4`

也就是在整个工作区间内几乎恒为 0，梯度可以忽略——它基本不再塑造策略，只剩下 0.05 的
常数权重。**注意一个容易踩的坑**：仅仅"改成按关节取平均"是恒等变换，因为
`12 × 0.1 = 1.2`，`exp(-1.2 · mean)` ≡ `exp(-0.1 · sum)`。真正的改动必须同时改尺度。

**改动**
`apply_velocity_reward_v2(env)`：

1. 速度项按关节数取均值，尺度从 0.1 改为 0.25，同一个工作区间被映射到
   `[0.53, 0.16]`（均值 0.34），梯度重新可用；
2. 五项的权重从 `pose 0.50 / vel 0.05 / ee 0.20 / root_pose 0.15 / root_vel 0.10`
   改为 `0.45 / 0.10 / 0.20 / 0.15 / 0.10`——从唯一有余量的姿态项让出 0.05，
   **五项权重和恒为 1.0**（代码里有断言）。这一点是关键：权重和为 1 意味着
   "每步奖励 ∈ [0,1] 且 1.0 = 完美跟踪"，`mean(reward)` 仍然等于论文 Table V 意义上的
   归一化回报，评估口径不用换。

**结果（同一段轨迹、只改奖励读数，策略行为不变）**

| 项 | 上游 v1 | v2 |
| --- | --- | --- |
| 速度项均值（确定性回合） | 0.0157 | **0.3376** |
| 速度项均值（随机相位 9 回合） | 0.0026 | **0.1909**（73×） |
| 速度项标准差 | 0.0210 | **0.1416**（6.7×） |
| 速度项 p10 / p90 | 0.0000 / 1.5e-4 | **0.161 / 0.530** |
| 同回合关节/根/偏航误差 | 0.0651 / 0.0241 / 0.0662 | 完全相同（策略未被改变） |
| 每步奖励（确定性回合） | 0.7496 | 0.7238 |

**边界（必须说清楚）**：这是纯训练侧改动，它的价值只有在重新训练后才能兑现。本机无 GPU，
论文每技能约 2e8 采样按实测 70 步/秒需要约 33 天/技能/种子，因此**没有**做端到端训练验证；
仓库只给出"奖励项已不再饱和"的直接证据和可直接复用的开关。也正因为改了尺度，
`--reward-v2` 下的奖励数值**不能**与论文/基线的奖励直接比大小，跨配置比较要看
关节误差、偏航误差、速度这些与奖励定义无关的量。

## 改进 3：多 seed / 随机相位评估协议

**问题**
上游 `eval_pretrained.py` 的评估是"5 个回合、每回合都从参考片段 t=0 开始"，
由于环境无随机化，5 个回合的逐帧数据完全一致——本质上是**一次确定性回放**，
既没有误差棒，也系统性高估/低估策略在真实起点分布下的表现。

**改动**
`src/evaluate.py` 提供论文式协议：

- `--seeds N`：多个随机种子，逐 `(seed, episode)` 从 `RandomState(1000·seed + ep)` 抽取起始相位；
- `--random-phase`：每回合在参考片段上随机取相位（与上游 `_enable_rand_init_time` 同分布，
  但**由本仓库显式生成**，因此跨进程可复现——上游采样器所依赖的 RNG 从外部无法固定）；
  参考 clip 是 `LoopMode.Wrap`、`is_over` 恒 False，所以随机起点不会导致提前终止；
- `--start-phases "0,0.25,0.5,0.75"`：确定性相位栅格，用于消融；
- 输出 `mean ± std`、末 5 s 窗口均值、偏航误差的最小二乘斜率 `yaw_drift_rad_per_s`
  （用来区分"有界周期误差"与"无界累积"），以及每回合的 `start_phase`；
- 每回合把 5 个奖励分项单独落盘，并在 `task.reward()` 内部 tee 出**该步实际使用的**分项值，
  用它们反算加权和与 `mean(reward)` 逐回合核对（`reward_matches_terms`）。

**结果：协议本身揭示了基线评估的偏差**

| 技能 | 单回合确定性（上游口径） | 3 seeds × 3 回合随机相位 | 差异 |
| --- | --- | --- | --- |
| dog_spin | 0.6378 | 0.6980 ± 0.0074 | +9.5% |
| dog_pace | 0.7496 | 0.7481 ± 0.0026 | −0.2% |

`dog_spin` 的确定性口径把成绩低估了近 10%（t=0 起步包含一段朝向误差累积的暂态，
而且只有一条轨迹、没有误差棒），这正是单回合评估最容易掩盖的问题。随机相位协议下
9 个回合的标准差 0.0074 也说明这个技能本身对起点并不敏感——低估值来自固定起点，而不是随机性。

## 可复现性：开关关闭时与上游逐位一致

`src/env_patch.py` 的三处 patch 都只在显式开关下生效（`--yaw-anchor` / `--reward-v2` /
`--random-phase`）。不带任何开关时，`src/evaluate.py` 跑出的数值与官方
`eval_pretrained.py` 完全一致（`dog_pace` 0.7496、`dog_spin` 0.6378，重复运行稳定），
因此新工具可以直接当作上游评估的替代品使用，而不会悄悄改变基线。

### 为了让"同一命令两次跑出同一数字"成立，踩过的两个坑

报告里的数字要求可复现，但官方栈在以下两处默认不可复现，均已在新工具中固定：

1. **TF/BLAS 线程数**：默认线程池下同一策略、同一种子在两次进程里会出现 1e-7 量级差异，
   对 `dog_spin` 这种接近稳定边界的步态足以让 600 步后轨迹分叉（实测同一配置两次跑出
   0.63 与 0.70）。`src/evaluate.py` 在导入 TF 前把 `OMP/MKL/OPENBLAS/NUMEXPR_NUM_THREADS`
   全部置 1。
2. **随机相位采样**：`ImitationTask._rand_uniform()` 在 env 没有 `np_random` 时回落到全局
   `np.random`，而该状态无法从外部固定，导致"随机相位"运行不可复现。新工具不再调用上游
   采样器，改为按 `(seed, episode)` 显式生成相位并写入 summary。

固定之后，同一条命令在两个独立进程里逐回合数值完全相同（已用 2 进程 × 2 回合 × 300 步
核对：`reward` 与 `start_phase` 完全一致）。

## 没有做、也建议不要当作已完成的事

- **潜在空间自适应 / AWR**（论文 4.2 节）：上游仓库没有实现，本仓库也没有补；
- **真机实验**（论文 Table IV）：无硬件；
- **论文 Table II 的训练超参**：上游 `run.py` 用的是 `4096 / 1 epoch / 1e-5`，
  与论文的 `10000 / 10 epochs / 2e-5` 不同，本仓库沿用上游以便对齐；
- **全量 PPO 训练复现**：算力不允许（见改进 2 的边界说明），只验证了管线与吞吐。
